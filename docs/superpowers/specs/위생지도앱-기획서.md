## 1. 왜 이 앱인가

### 문제
음식을 시키거나 외식할 때, **"이 가게 위생 괜찮나?"** 는 누구나 궁금하지만 확인할 길이 없다.
식약처가 위반 업소 정보를 **공식적으로 공개**하고 있지만(식품위생법 제84조), 일반인이 찾아보기엔 흩어져 있고 불편하다.

### 우리의 답
공개된 공식 데이터를 **지도 위에, 검색 한 번에** 올려놓는다.

> 🔑 **핵심 한 줄**
> "위반을 **폭로**하는 앱"이 아니라, "안심을 **확인**해 주는 앱"이다.
> 깨끗한 가게엔 ✅, 문제 있는 가게엔 ⚠️ — **양방향으로 명확하게** 답한다.

이 방향성이 앱의 정체성이자, 법적·도덕적 안전성의 토대다.

## 2. 핵심 기능 (1차 출시 MVP)

> 원칙: **진지한 제품일수록 처음엔 핵심에 집중한다.** 다 넣으려다 출시를 못 하는 함정을 피한다.

| 기능 | 설명 | 1차 |
|---|---|:---:|
| 🗺️ **지도** | 내 주변 **위생등급 지정** 가게가 캐릭터 핀으로 표시 | ✅ |
| 🍗 **종목 선택** | 치킨 / 피자 / 중식 / 족발보쌈 등 배달 종목별로 보기 (1차는 치킨 중심) | ✅ |

| 📋 **상세** | 위생등급 지정일·유효기간, (있으면) 위생 처분 내용·날짜·근거 법령 | ✅ |

## 3. 어떻게 동작하나 — 시스템 구조

이 앱의 난이도는 **화면이 아니라 데이터**에 있다. 그리고 그 부분이 바로 **우리 팀의 백엔드 강점이 빛나는 곳**이다.

```
 [데이터 소스]              [백엔드 — 우리의 핵심 경쟁력]            [앱 — Flutter]
 ┌──────────────┐         ┌──────────────────────────┐         ┌──────────────┐
 │ 식약처        │         │ ① 수집   (배치 스케줄러)   │         │  지도 화면     │
 │  · 위생등급 API│ ──────▶ │ ② 지오코딩(주소 → 좌표)   │ ──API──▶│  검색 화면     │
 │  · 행정처분 API│         │ ③ 저장   (PostgreSQL+    │         │  상세 화면     │
 │               │         │          PostGIS)        │         │  즐겨찾기      │
 └──────────────┘         │ ④ 제공   (검색·지도 API)  │         └──────────────┘
                          └──────────────────────────┘
```

### 3계층 설명
1. **데이터 소스** — 식약처(식품안전나라) Open API. 키 하나에 **서비스별로 활용신청** 필요, 같은 키로 **동시 요청 불가**
   - **C004 위생등급 지정 현황** (주인공): 전국 47,020건, 3지역 유효 지정 7,377곳. 1회 최대 500건
   - **I2630 행정처분결과(식품접객업)** (보조): 현재 공표 중인 처분만, 전국 2,737건. 1회 최대 1000건
   - 두 데이터는 **인허가번호(`LCNS_NO`)**로 연결된다
   - *(추후)* 지자체 음식점 인허가 데이터 — 업태구분(중국식 등)으로 종목 정확도 개선. 제공 여부 확인 필요
2. **백엔드** — 수집 → 지오코딩 → 저장 → 제공의 파이프라인. **여기가 제품의 진짜 엔진.**
3. **앱(Flutter)** — 하나의 코드로 iOS·Android·웹까지. 사용자가 만나는 얼굴.

## 4. 기술 선택과 이유

| 영역 | 선택 | 왜 |
|---|---|---|
| **앱** | **Flutter** | 언어 하나(Dart)로 iOS+Android+웹. **Material 3 디자인 기본 내장** → 디자인 약점 보완. 지도 패키지 성숙 |
| **DB** | **PostgreSQL + PostGIS** | "내 주변 N km 가게" 같은 **위치 검색에 특화**. 지도 앱의 필수 도구 |
| **백엔드 언어** | **Python** (확정) | 데이터 수집·가공에 편함. API 서버는 FastAPI 예정 |
| **지오코딩** | 카카오/네이버/구글 지오코딩 API 중 택1 | 주소 → 좌표 변환. 무료 한도·정확도 비교 후 결정 |

> 💡 **모바일이 처음이어도 괜찮은 이유**: 어려운 일(데이터 파이프라인)은 이미 잘하는 영역이고, 새로 배우는 Flutter는 화면 부분이라 진입이 비교적 완만하다.

## 5. 디자인 차별화 전략 — "예쁘게"가 아니라 "명확하게"

팀이 디자인에 약하다는 점을 **정면으로 인정하고**, 거기에 맞는 전략으로 간다.

> 디자인 초보가 화려함으로 이기려 하면 진다. **명확함**으로 이긴다.

1. **🐣 캐릭터 핀** — 신호등 3색 대신, 표정이 바뀌는 캐릭터로 상태를 보여준다 (개정)
   | 상태 | 캐릭터 표현 (예시) |
   |---|---|
   | ⭐ 위생등급 지정 | 반짝이며 웃는 얼굴 + 별 배지 — **앱의 주인공** |
   | 공표 중인 위생 처분 없음 | 평온한 기본 얼굴 |
   | ⚠️ 위생 처분 있음 | 걱정 표정 + 돋보기/느낌표 |
   - 위반 가게 캐릭터는 **"주의하세요"까지만**. 더럽다·조롱하는 표현 금지 (명예훼손 위험, "확인" 원칙)
   - 캐릭터 종류는 미정: 밥그릇·숟가락 / 동물 마스코트 / 비누방울 중 선택. 기존 `untitled.pen`의 `PinGreen` 핀을 교체하는 방식
2. **검증된 디자인 시스템 차용** — Material 3 + 무료 컴포넌트 킷. **바닥부터 안 만든다.**
3. **핵심 화면 1~2개에만 공들이기** — 특히 **상세("위생 성적표") 화면**에 집중 투자
4. **레퍼런스 + 무료 템플릿 활용** — 참고 앱 리서치, Figma 무료 템플릿 (필요 시 함께 탐색)

## 6. 데이터 모델 (핵심 3개 테이블, 개정)

```
                 ┌─────────────────────────┐
                 │  restaurants (음식점)     │
                 ├─────────────────────────┤
                 │ 인허가번호 LCNS_NO (PK)   │
                 │ 가게명 · 주소 · 좌표       │
                 │ 업종 · 배달 종목(치킨 등)  │
                 └─────────────────────────┘
                    1 │              │ 1
          ┌───────────┘              └───────────┐
        N ▼                                     N ▼
┌─────────────────────────┐         ┌─────────────────────────┐
│ hygiene_grades (위생등급) │         │  violations (행정처분)    │
├─────────────────────────┤         ├─────────────────────────┤
│ 지정번호 · 등급(적합)      │         │ 위반 내용 · 처분 종류      │
│ 지정 시작일 · 종료일       │         │ 처분 일자 · 근거 법령      │
│ 지정 취소일 · 영업 상태    │         │ 분류 CATEGORY            │
└─────────────────────────┘         └─────────────────────────┘
```

- 가게를 잇는 키는 **인허가번호** — 이름·주소 매칭 불필요
- 위생등급은 **유효한 지정만** 저장: 지정종료일 ≥ 오늘, 취소 안 됨, 영업상태 "정상"
- 행정처분 분류(`pipeline/classify.py`, 위반 내용 키워드 기준):

  | 분류 | 3지역 건수 | 앱에서 |
  |---|---|---|
  | `hygiene` 위생 (소비기한 경과, 수질검사 미실시, 복어 독 등) | 5 | ⚠️ 위생 경고 |
  | `conduct` 영업질서 (청소년 주류, 유흥접객, 도박 등) | 32 | 위생과 무관 — **표시 방식 미정** |
  | `closed` 행정 정리 (철거·멸실·폐업·장기휴업) | 526 | 이미 없는 가게 → 지도에서 제외 |
  | `unknown` 분류 불가 (법 조항만 있음) | 2 | 경고하지 않음 (근거 없음) |

- 배달 종목은 1차로 **가게 이름 키워드로 추정** (`pipeline/cuisine.py`). 3지역 위생등급 업소 기준: 치킨 852 · 피자 188 · 마라탕 32 · 족발보쌈 19 · 중식 10

## 7. 법적 안전장치 (진지한 출시엔 타협 불가)

공식 데이터 기반이라 토대는 단단하지만, "진지한 제품"이라면 다음을 **반드시** 지킨다.

| 장치 | 내용 |
|---|---|
| ✅ **공식 데이터만** | 식약처 공개 자료만 표시. 임의 정보·추측 절대 추가 금지 |
| ✅ **출처·기준일 명시** | 모든 정보에 "식약처 / 기준일 YYYY-MM-DD" 표기 |
| ✅ **면책 고지** | "본 정보는 식약처 공개 자료(위생등급·행정처분)이며 현재 상태와 다를 수 있습니다" |
| ✅ **정정 요청 채널** | 업주가 이의제기·정정 요청할 수 있는 창구 마련 |
| ✅ **표시 기간 정책** | 데이터 출처 정책을 따른다: 행정처분은 **공표 기간 중인 것만**, 위생등급은 **유효기간 내 지정만** (개정) |
| ✅ **없는 것을 단정하지 않기** | "위반 없음"이 아니라 **"현재 공표 중인 위생 처분 없음"**. 위생등급이 없다고 낮게 표현하지 않음 (등급은 신청제) |

> ⚖️ 핵심: 우리는 **이미 공개된 공식 정보를 보기 좋게 재가공**하는 것이지, 새로운 폭로를 하는 것이 아니다. 이 선을 지키는 것이 곧 안전장치다.

```

        식약처 수집 → 지오코딩 → DB 적재. "엔진"부터 만든다.

1단계  코어 기능       ░░████████░░
        검색·지도 API + Flutter 기본 3화면 (지도/검색/상세)

2단계  완성도          ░░░░██████░░
        필터 · 즐겨찾기 · 디자인 다듬기 · 법적 고지 적용

3단계  출시 & 성장      ░░░░░░████░░
        경남·경북·부산 출시 → 반응 측정 → 알림·전국확장·수익화
```
